신입 개발자 멘토링은 3개월 동안 Spring과 React 과제를 중심으로 진행합니다. 매주 금요일 오전에 발표가 있고, 매월 마지막 주 금요일에는 그달의 과제를 시연합니다. 3개월 차에는 팀 프로젝트로 실무 흐름을 경험합니다.

| 구분 | 기간 | 주제 |
| --- | --- | --- |
| 1개월 차 | 1~4주 | 협업 기초와 Spring 백엔드 |
| 2개월 차 | 5~8주 | React와 풀스택 연동 |
| 3개월 차 | 9~12주 | 팀 프로젝트와 실무 경험 |

## 운영 원칙

**매월 과제 시연**
4주, 8주, 12주 차 금요일 오전에 그달 만든 결과물을 시연하고, 설계 의도와 문제를 해결한 과정을 발표합니다.

**주간 기술 발표**
과제 시연 주가 아닌 주에는 매주 금요일 오전에 참여자 모두 그 주 주제에서 서로 다른 소주제를 하나씩 맡아 10분씩 발표합니다.

**상호 코드리뷰**
모든 과제는 PR로 제출하고, 멘토 리뷰 전에 동기 두 명의 리뷰를 먼저 받습니다.

## 1개월 차: 협업 기초와 Spring 백엔드

### 1주 차: 온보딩과 Git 협업

- **학습**: 개발환경 세팅, Git/GitHub 협업(브랜치 전략, PR, 커밋 컨벤션), 사내 코드 컨벤션, 업무 도구 사용법, curl과 Postman, 브라우저 개발자도구 Network 탭 사용법
- **과제**: 실습 레포에 자기소개 PR 올리고 서로 코드리뷰하기, 충돌 해결 실습, 2주 차 대비 Java 핵심(컬렉션, 스트림, 예외) 사전 학습

### 2주 차: HTTP와 Spring Boot 기초

- **학습**: HTTP 요청과 응답 구조, 메서드, 상태 코드, 헤더, Content-Type, IoC/DI, Bean, 레이어드 아키텍처, REST API 설계 원칙
- **과제**: 회원 API 설계 및 구현

### 3주 차: JPA와 데이터베이스

- **학습**: 엔티티와 연관관계, 영속성 컨텍스트, N+1 문제, SQL 기본과 인덱스
- **과제**: 게시판 CRUD API(게시글, 댓글)

### 4주 차: 품질 다듬기와 과제 시연

- **학습**: 예외 처리 전략, Validation, 테스트 코드(JUnit, MockMvc), Swagger로 API 문서화
- **과제**: 게시판 API에 테스트 코드와 API 문서 추가

## 2개월 차: React와 풀스택 연동

### 5주 차: JavaScript와 React 기초

- **학습**: 브라우저에 URL을 입력하면 일어나는 일(DNS, TCP 연결, 요청, 렌더링), ES6+, 비동기(Promise, async/await), TypeScript 기초, 컴포넌트, props, state
- **과제**: 게시판 화면 정적 UI 구현

### 6주 차: Hooks, 라우팅, API 연동

- **학습**: useState, useEffect, 커스텀 훅, React Router, 상태관리(Context 또는 Zustand), React Query
- **과제**: 1개월 차 API와 화면 연동

### 7주 차: 인증과 보안 기초

- **학습**: 쿠키와 세션, JWT 비교, HTTPS와 TLS 기초, CORS와 Same-Origin Policy, Spring Security 기초, 프론트 로그인 처리
- **과제**: 로그인과 회원가입 기능 연동

### 8주 차: 풀스택 완성과 과제 시연

- **학습**: 리팩토링, 공통 컴포넌트 분리, 에러와 로딩 처리, 코드리뷰 반영
- **과제**: 개인 풀스택 게시판 완성

## 3개월 차: 팀 프로젝트와 실무 경험

### 9주 차: 팀 프로젝트 킥오프

- **학습**: 요구사항 분석, ERD 설계, API 명세 작성, 역할 분담, 이슈 관리, 스프린트 방식
- **과제**: 3인 팀 기획서, ERD, API 명세 작성

### 10주 차: 스프린트 1

- **학습**: 로깅과 디버깅 방법, 실전 코드리뷰
- **과제**: 핵심 기능 개발

### 11주 차: 스프린트 2와 배포

- **학습**: Docker 기초, CI/CD(GitHub Actions), 도메인과 포트, 리버스 프록시(Nginx), 로드밸런서 개념, 배포 과정
- **과제**: 기능 마무리 및 배포

### 12주 차: 최종 발표와 회고

- **학습**: 성능과 보안 점검, KPT 회고, 문서 정리
- **과제**: 최종 산출물 정리

## 이런 부분을 중요하게 봅니다

과제, 발표, 협업 과정 전반에서 아래 다섯 가지를 중요하게 봅니다.

| 항목 | 내용 |
| --- | --- |
| 기술 역량 | 과제 완성도, 요구사항 충족 |
| 코드 품질 | 가독성, 구조, 테스트 |
| 문제 해결력 | 스스로 찾아보고 적절히 질문하는지 |
| 커뮤니케이션 | 발표, 코드리뷰, 진행 상황 공유 |
| 협업과 태도 | 피드백 수용, 팀워크 |

## 일정 외에 스스로 공부하면 좋은 것

### 기본기

- HTTP와 네트워크: 과제 중에도 개발자도구로 요청과 응답을 확인하는 습관 들이기
- DB: SQL 직접 작성, 인덱스, 트랜잭션과 격리 수준
- Linux 기본 명령어: 파일 탐색, 로그 확인, 프로세스 확인

### 실무 도구

- Git 심화: rebase, cherry-pick, 충돌 해결
- 클라우드 기초: EC2, RDS, S3가 각각 무엇인지

### 코드 품질

- 클린 코드와 리팩토링
- OWASP Top 10 수준의 보안 지식: SQL Injection, XSS, CSRF

### 일하는 방식

- 질문을 잘하는 법: 시도한 것, 에러 메시지, 예상 결과 정리
- 진행 상황과 일정 리스크를 미리 공유하는 습관
- 코드리뷰를 주고받는 태도
- 공식 문서를 먼저 찾아보는 습관
